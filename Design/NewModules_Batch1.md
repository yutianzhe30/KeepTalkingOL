# 🌟 新模块设计提案 - 异步双人合作模式 (Batch 1)

> 文档状态：设计草案
> 游戏模式：双人异步合作（拆弹者 + 手册持有者）
> 核心机制：**信息分割 + 语言描述 + 沟通误差**

---

## 核心设计原则回顾
1. **信息不对等架构**：拆弹者负责观察和操作，手册持有者负责查阅规则和计算。
2. **沟通与转译**：双方都需要将看到的信息转换为语言，并理解对方的语言描述。

---

## 新模块提案

### 1. 🌌 星图观测模块 (Star Map Observation)

#### 核心机制
拆弹者像在使用望远镜观测星空，只能看到星星的分布；手册持有者拥有星图手册，需要根据分布特征识别星座并给出坐标。

#### 拆弹者屏幕
```
┌─────────────────┐
│     [▲]         │
│  [◀] 🔭 [▶]    │  ← 望远镜视野控制器
│     [▼]         │
│                 │
│  ★     ★       │
│    ★      ★    │  ← 视野中可见的星星（连线不可见）
│  ★     ★       │
│                 │
│ [坐标X] [坐标Y]  │  ← 需要输入的最终解
│  [锁定目标]      │
└─────────────────┘
```
- 视野有限，只能看到部分星空，可以通过方向键移动视野。
- 只有星星的散点分布，没有星座连线。
- 视野中可能有一颗闪烁红光的"异常星"或目标。

#### 手册持有者屏幕
```
┌──────────────────────────────────────────┐
│ 星空导览手册                              │
├──────────────────────────────────────────┤
│ 1. 识别星座                              │
│ 询问拆弹者看到的星星分布规律：            │
│ • "像一个勺子" → 大熊座 (坐标偏移: X+2, Y-1)│
│ • "像一个大十字" → 天鹅座 (坐标偏移: X-3, Y+4)│
│ • "像一个W" → 仙后座 (坐标偏移: X+5, Y+5)  │
│                                          │
│ 2. 计算目标坐标                           │
│ 基础坐标 = 星座中心点坐标（见附表）        │
│ 最终坐标X = 基础X + 坐标偏移X             │
│ 最终坐标Y = 基础Y + 坐标偏移Y             │
│                                          │
│ 3. 特殊规则                              │
│ 如果序列号中包含字母'S'，所有最终坐标取反  │
│ (例如 X=5 变成 X=-5)                     │
└──────────────────────────────────────────┘
```

#### 沟通流程示例
**拆弹者**: "我在视野里看到大概5、6颗星星，排成一个类似'W'的形状。"
**手册持有者**: "W形状？那是仙后座。你在附近有看到闪烁的红星吗？"
**拆弹者**: "红星...等一下我移动一下视野...啊，在W的右下角有一颗红星。"
**手册持有者**: "好，仙后座的基础中心坐标是 (12, 8)。偏移是 X+5, Y+5。所以是 (17, 13)。等等，炸弹序列号里有字母 'S' 吗？"
**拆弹者**: "有，序列号是 S9K2M。"
**手册持有者**: "那坐标全部取反，输入 X=-17, Y=-13，然后锁定。"

#### 设计亮点
- **空间描述**：拆弹者需要用语言描述散点构成的形状。
- **视野限制**：拆弹者需要移动视野寻找全貌，增加了时间消耗和操作感。

### 2. 🧪 化学调和模块 (Chemistry Mixer)

#### 核心机制
拆弹者面前有各种颜色的化学试剂和加热装置；手册持有者需要根据颜色和标签指导正确的混合顺序和加热温度。

#### 拆弹者屏幕
```
┌─────────────────┐
│  [烧杯] (空)     │  ← 混合容器，显示当前颜色和温度
│  当前温度: 20°C  │
│                 │
│  [红色液体] (A)  │
│  [蓝色液体] (B)  │  ← 试剂瓶，带颜色和字母标签
│  [绿色液体] (C)  │
│                 │
│  [滴入] [加热]   │  ← 操作按钮
│  [冷却] [倒掉]   │
└─────────────────┘
```
- 可以选择试剂滴入烧杯。
- 烧杯内液体颜色会随着混合发生变化。
- 可以控制加热或冷却。
- "倒掉"用于清空重来（可能带有轻微的时间惩罚）。

#### 手册持有者屏幕
```
┌──────────────────────────────────────────┐
│ 化学安全操作手册                          │
├──────────────────────────────────────────┤
│ 步骤 1：确认试剂                         │
│ 询问拆弹者有哪些颜色的试剂，以及对应的字母标签。│
│                                          │
│ 步骤 2：决定配方                         │
│ 检查炸弹上的电池数量：                    │
│ • 电池数 >= 3：配方 Alpha (红+蓝 -> 加热至50度 -> 加绿)│
│ • 电池数 < 3：配方 Beta (绿+蓝 -> 冷却至10度 -> 加红) │
│                                          │
│ 注意：如果试剂标签与说明书规定不符（例如：红色不是A），│
│ 则需反转操作顺序！                        │
└──────────────────────────────────────────┘
```

#### 沟通流程示例
**手册持有者**: "你那边有哪些颜色的液体？标签分别是什么？"
**拆弹者**: "红色的写着A，蓝色的B，绿色的C。"
**手册持有者**: "好的，炸弹上有几节电池？"
**拆弹者**: "2节。"
**手册持有者**: "电池少于3，用Beta配方。先滴入绿色，再滴入蓝色。"
**拆弹者**: "[操作] 滴了绿和蓝，现在烧杯里是青色的。"
**手册持有者**: "对，现在按冷却，降到10度。"
**拆弹者**: "[操作] 到了10度了。"
**手册持有者**: "最后滴入红色。"
**拆弹者**: "[操作] 完成！模块绿灯了。"

#### 设计亮点
- **多步状态管理**：不再是一次性输入，而是需要按顺序进行多个操作（滴入、调温）。
- **不可逆操作**：如果滴错，需要"倒掉"重来，增加容错成本。

### 3. 📡 声纳雷达模块 (Sonar Radar)

#### 核心机制
拆弹者看着一个类似潜艇雷达的屏幕，不断扫描出光点；手册持有者根据光点的位置和特征，判断哪些是"敌方目标"需要消除，哪些是"友军"需要保留。

#### 拆弹者屏幕
```
┌─────────────────┐
│    N (0°)       │
│  W ⊕ E         │  ← 雷达扫描界面，⊕为中心点
│    S (180°)     │
│                 │
│ 目标1: 45° 距离3  │
│ 目标2: 120° 距离5 │  ← 雷达扫描到的光点数据
│                 │
│ [输入角度] [输入距离]│
│    [发射鱼雷]     │
└─────────────────┘
```
- 雷达线持续扫描，光点会慢慢闪烁。
- 拆弹者可以读取每个光点的极坐标（角度和距离）。
- 需要输入特定坐标并"发射鱼雷"来消除光点。

#### 手册持有者屏幕
```
┌──────────────────────────────────────────┐
│ 声纳目标识别手册                          │
├──────────────────────────────────────────┤
│ 根据序列号末尾数字判断威胁：              │
│ 末位偶数：                                │
│ • 距离 < 4 且 角度在 0°-90° 之间的是敌军。 │
│ • 距离 >= 4 且 角度在 180°-270° 之间的是敌军。│
│                                          │
│ 末位奇数：                                │
│ • 距离 < 3 都是友军，切勿攻击！           │
│ • 角度在 90°-180° 之间的都是敌军。         │
│                                          │
│ 任务：发射鱼雷摧毁所有敌军目标。            │
│ 警告：击中友军目标会立即增加一次失误记录！    │
└──────────────────────────────────────────┘
```

#### 沟通流程示例
**拆弹者**: "雷达扫到了两个目标。目标1在45度，距离3；目标2在120度，距离5。"
**手册持有者**: "序列号末位是奇数还是偶数？"
**拆弹者**: "末位是 7，奇数。"
**手册持有者**: "奇数的话... 距离小于3是友军。角度在90到180度之间是敌军。目标2在120度，距离5，所以目标2是敌军！"
**拆弹者**: "那目标1呢？45度，距离3。"
**手册持有者**: "45度不在敌军范围内，距离3也不在绝对友军范围...保险起见先别动目标1。先向120度距离5发射鱼雷！"
**拆弹者**: "[输入 120, 5] 发射！击中了，目标2消失了。"

#### 设计亮点
- **持续沟通与核对**：需要针对每一个出现的目标进行"描述-判断"的循环。
- **高风险惩罚**：误伤友军直接失误，迫使双方必须非常谨慎地核对数据。
