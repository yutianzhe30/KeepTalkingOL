# 🚀 原创模块设计 - 创新机制实验

> 跳出传统KTANE框架，创造全新的双人异步交互体验

---

## 设计理念突破

### 传统框架
- 拆弹者看见 → 描述 → 手册查表 → 给指令 → 执行

### 新框架实验
| 新机制 | 核心体验 |
|--------|----------|
| **双向信息差** | 两人各自有对方不知道的信息，必须互相询问 |
| **时间错位** | 拆弹者现在看到的，是手册持有者过去/未来的状态 |
| **感知干扰** | 拆弹者的感官被主动干扰，需要"校准" |
| **共同构建** | 两人一起拼凑出完整的解题图景 |

---

## 原创模块

### 1. 🪞 镜像错位 (Mirror Misalignment)

#### 核心创新
拆弹者和手册持有者看到的是**同一事物的不同投影**，需要建立坐标映射。

#### 拆弹者屏幕
```
┌─────────────────┐
│      北         │
│   ┌───────┐     │
│ 西│  ●──→ │东   │  ← 一个可移动的指针
│   │  ↓    │     │     和4个方向的障碍
│   └───────┘     │
│      南         │
│                 │
│ [↑][↓][←][→]   │
└─────────────────┘
正常视角的迷宫
```

#### 手册持有者屏幕
```
┌─────────────────┐
│    解法路径     │
│   ┌───────┐     │
│   │ →→↓   │     │  ← 显示正确的移动路径
│   │   ↓   │     │     但整个视图是旋转的！
│   └───────┘     │
│                 │
│ 视角: 顺时针90° │  ← 告诉手册持有者当前的旋转角度
│                 │
│ "让指针从起点   │
│  向东走2格,     │
│  再向南走2格"   │
└─────────────────┘
```

#### 随机变换（每局不同）
| 变换类型 | 拆弹者看到 | 手册持有者指令 |
|---------|-----------|---------------|
| 旋转90° | 东 = 手册的北 | 需说"向左走"而非"向北" |
| 旋转180° | 上下左右全反 | 完全反向指令 |
| 镜像翻转 | 左右相反 | "东"实际是"西" |

#### 沟通过程
```
手册持有者: "从中心出发，先向东走2格"
拆弹者: [按东，但撞墙] "撞墙了"
手册持有者: [意识到有旋转] "等等，你的北在哪？"
拆弹者: "上方"
手册持有者: "我的视图是顺时针转了90度的"
手册持有者: "那我说的东其实是你的...让我想想..."
手册持有者: "走你的右边，走2格"
```

#### 为什么原创
- **双向推导**：不是简单的描述-查表，而是两人都要做空间转换
- **元沟通**：需要讨论"如何讨论"才能建立共同语言
- **错误累积**：一次方向混淆会导致后续全部错误

### 2. 🌊 回声定位 (Echo Location)

#### 核心创新
拆弹者是"盲人"，只能听到声音；手册持有者是"聋子"，只能看到地图。两人必须合成完整信息。

#### 拆弹者体验
```
屏幕：黑屏，只有波形显示

拆弹者点击[发送声波] → 听到回响：
• "滴——滴滴" (短长短 = 近处有障碍)
• "滴——————" (长 = 远处有障碍)
• 无声 = 该方向空旷

需要向手册持有者描述听到的节奏模式
```

#### 手册持有者屏幕
```
┌─────────────────┐
│   声波对照表     │
├─────────────────┤
│ 短音(0.2s) = 1格 │
│ 长音(0.6s) = 3格 │
│ 静音 = 空旷      │
├─────────────────┤
│   地图布局      │
│ ┌───┬───┬───┐  │
│ │ S │   │ █ │  │  S=起点, █=障碍
│ ├───┼───┼───┤  │
│ │   │ █ │   │  │
│ ├───┼───┼───┤  │
│ │   │   │ E │  │  E=终点
│ └───┴───┴───┘  │
├─────────────────┤
│ 根据拆弹者的描述 │
│ 确定他在哪个位置 │
│ 然后指挥他走到E  │
└─────────────────┘
```

#### 协作流程
```
拆弹者: [向北发声波] "北：短长短"
手册持有者: [对照] "北边1格有障碍，3格外还有障碍"
手册持有者: "你在左下角，北边能走2格"
拆弹者: [向北走2格] "新位置，东：短长"
手册持有者: "东边1格障碍，3格外空旷"
手册持有者: "可以向东走，但要小心"
...（直到到达终点）
```

#### 升级机制
- 后期加入"噪音干扰"：拆弹者听到的声音有杂音
- 手册持有者需要告诉拆弹者"调谐"哪个频率（点击不同滤波器）

### 3. ⏳ 时间胶囊 (Time Capsule)

#### 核心创新
模块会记录**过去30秒内的关键事件**，手册持有者需要通过提问来"考古"。

#### 拆弹者屏幕（当前）
```
┌─────────────────┐
│  当前状态: 等待  │
│                 │
│  闪烁数字: 7    │  ← 一个数字在1-9之间缓慢变化
│                 │
│  [记录此刻]     │  ← 可以按按钮"拍照"
│                 │
│  已记录: 3/5    │  ← 已经存了3个时间点
└─────────────────┘
```

#### 手册持有者屏幕
```
┌─────────────────┐
│  时间胶囊解密    │
├─────────────────┤
│ 你已通过拆弹者   │
│ 记录了5个时间点  │
│                 │
│ 现在回答：       │
│ "第2个记录的数字 │
│  比第4个大吗？"  │
│                 │
│ [是] [否] [未知] │
├─────────────────┤
│ 需要连续答对     │
│ 3个问题才能解锁  │
│                 │
│ 问题类型：       │
│ • 比较大小       │
│ • 奇偶性         │
│ • 相邻记录的差值 │
└─────────────────┘
```

#### 关键设计
- 拆弹者**不知道**记录了什么，只是按按钮"存下这一刻"
- 手册持有者**不知道**具体数字，只能问是非题
- 两人需要**规划记录策略**："存一下""再存一下""好现在可以回答了"

#### 为什么折磨人
```
手册持有者: "第一个记录的数字是奇数吗？"
拆弹者: "...我不知道，我没看那时候是多少"
→ 两人意识到需要更精确的配合
```

### 4. 🌀 语义漂移 (Semantic Drift)

#### 核心创新
拆弹者界面的**文字会逐渐变成乱码/其他语言**，手册持有者需要教他"翻译"。

#### 第一阶段（正常）
```
拆弹者看到：
┌─────────────────┐
│  按下红色按钮   │
│  等待3秒       │
│  然后剪断蓝线   │
└─────────────────┘
手册持有者看到同样的指令
```

#### 第二阶段（开始漂移）
```
拆弹者看到：
┌─────────────────┐
│  按下 红● 按钮  │  ← "色"变成方块
│  等待3秒       │
│  然后剪断 ■线   │  ← "蓝"变成方块
└─────────────────┘
```

#### 第三阶段（严重漂移）
```
拆弹者看到：
┌─────────────────┐
│  Press [R●d]   │  ← 变成英文+乱码
│  wait 3s       │
│  cut [Bl■] wire│
└─────────────────┘
```

#### 手册持有者的作用
```
手册持有者拥有一张"翻译表"：

漂移阶段1：中文方块 = 原文字的一半
漂移阶段2：英文 = 需要回译
漂移阶段3：乱码 = 根据位置推断

手册持有者需要通过描述告诉拆弹者：
"那个方块在'红'字的右边，应该是'色'"
"英文R●d就是红色的意思"
```

#### 机制深度
- 漂移速度会随着时间加快
- 两人需要**赶在变无法阅读前完成操作**
- 创造"在信息消失前抢救它"的紧迫感

### 5. 👁️ 盲区互补 (Blind Spot)

#### 核心创新
拆弹者和手册持有者各自看到拼图的一部分，必须**描述自己的部分**让对方画出完整图景。

#### 拆弹者看到（左半部分）
```
┌────────┬───────┐
│ ████   │ ？？？│  ← 右边被遮蔽
│ █  █   │ ？？？│
│ ████   │ ？？？│
├────────┼───────┤
│   ██   │ ？？？│
│   ██   │ ？？？│
│ ██████ │ ？？？│
└────────┴───────┘
只有左侧可见
```

#### 手册持有者看到（右半部分）
```
┌───────┬────────┐
│ ？？？│    ██  │  ← 左边被遮蔽
│ ？？？│   █  █ │
│ ？？？│    ██  │
├───────┼────────┤
│ ？？？│ ███    │
│ ？？？│ █  ███ │
│ ？？？│ ███    │
└───────┴────────┘
只有右侧可见
```

#### 任务
两人需要合作识别这是哪个数字/字母/符号。

#### 沟通示例
```
拆弹者: "我左边是个像'日'字的形状，但下面出头了"
手册持有者: "我右边是个圆形，但右边缺了一块"
拆弹者: "等等，你说圆形缺一块，是左缺还是右缺？"
手册持有者: "左边缺，像个C字反过来"
拆弹者: "那就是'D'！但我的部分像'B'..."
→ 两人意识到是数字'8'，但各自只看到一半
```

### 6. 🔥 熵减协议 (Entropy Reduction)

#### 核心创新
模块会**越来越混乱**，两人需要快速完成一系列**递减的整理动作**来逆转熵增。

#### 混乱度等级
```
等级5（初始）: [1][2][3][4][5][6]  完全有序
等级4:         [2][1][4][3][6][5]  相邻交换
等级3:         [4][1][6][3][2][5]  随机打乱
等级2:         [?][?][?][?][?][?]  数字变成？
等级1（临界）:  [!][!][!][!][!][!]  即将爆炸
```

#### 拆弹者操作
```
┌─────────────────┐
│  当前混乱度: 3   │
│                 │
│  [4][1][6][3][2][5] │  ← 6个可以拖动的方块
│                 │
│  [  排序  ]      │  ← 按当前顺序确认
│                 │
│  注意：每10秒    │
│  混乱度+1       │
└─────────────────┘
```

#### 手册持有者规则
```
根据当前混乱度等级，确定"正确顺序"：

等级5: 已经是1-2-3-4-5-6，直接确认
等级4: 需要变成1-3-5-2-4-6（奇偶分离）
等级3: 需要按数字之和=10配对 (1-4-5, 2-3-5不对...)
       实际是 [1][2][3]在前，[4][5][6]在后
等级2: 需要猜数字（根据之前看到的）
等级1: 来不及了！随机猜！
```

#### 关键设计
- **时间压力**：必须在降级前完成当前等级的整理
- **记忆负担**：等级2时需要记住等级3时看到的数字
- **策略选择**：有时故意不整理，等降一级后用更简单的规则

## 建议组合

### "沟通地狱"组合
- 镜像错位 + 回声定位 + 盲区互补
- **体验**：全程高能描述，极度烧脑

### "信息衰减"组合  
- 时间胶囊 + 语义漂移 + 熵减协议
- **体验**：与时间赛跑，信息在不断消失
