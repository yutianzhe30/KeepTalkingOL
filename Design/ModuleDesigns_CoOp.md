# 🎮 新模块设计提案 - 异步双人合作模式

> 文档状态：审阅中  
> 游戏模式：双人异步合作（拆弹者 + 手册持有者）
> 核心机制：**信息分割 + 语言描述 + 沟通误差**

---

## 核心设计原则

### 1. 信息不对等架构
```
┌─────────────────┐          语言描述           ┌─────────────────┐
│   拆弹者        │  ◄──────────────────────►  │  手册持有者      │
│  (游戏客户端)    │    （只能说话，不能看图）     │  (说明书/Manual) │
│                 │                            │                 │
│ • 看到具体图案   │                            │ • 知道解题规则   │
│ • 听到声音      │                            │ • 有对照表格    │
│ • 能操作模块    │                            │ • 不知道当前状态 │
└─────────────────┘                            └─────────────────┘
```

### 2. 三大设计支柱

| 支柱 | 说明 | 示例 |
|------|------|------|
| **可描述性** | 拆弹者能用语言准确描述所见 | "左上角有个像鱼叉的符号" |
| **规则复杂性** | 手册持有者需要查表/计算才能给出指令 | "奇数位置的红线，剪第3根" |
| **错误空间** | 描述不清或理解错误会导致错误操作 | 把"钩子"说成"弯线"剪错线 |

## 新模块提案

### 1. 🔊 摩斯电码模块 (Morse Code) ✅ 推荐优先实现

#### 信息分割设计

**拆弹者看到：**
```
┌─────────────────┐
│  🔴 [闪烁LED]    │  ← 每秒闪烁摩斯码
│                 │
│  频率: [__][__]  │  ← 两位数字输入框
│                 │
│  [  发送  ]      │
└─────────────────┘
```
- LED 以摩斯电码闪烁（如 `···−`）
- 不知道这是哪个字母
- 只能描述"短长短长"或"滴滴答"

**手册持有者拥有：**
```
摩斯电码对照表
┌─────────┬──────────┬────────┐
│ 字母    │ 摩斯码    │ 频率   │
├─────────┼──────────┼────────┤
│ A       │ · −      │ 35     │
│ B       │ − · · ·  │ 12     │
│ V       │ · · · −  │ 58     │
│ ...     │ ...      │ ...    │
└─────────┴──────────┴────────┘

特殊规则：
• 序列号含元音 → 使用左侧频率表
• 否则 → 使用右侧频率表（数字+10）
```

#### 沟通流程
```
拆弹者: "LED在闪，节奏是 短短短长"
手册持有者: [查表] "那是字母 V，对应频率 58"
手册持有者: "输入 5 和 8，但要确认序列号有没有元音？"
拆弹者: "序列号是 X7K2M9，没有元音"
手册持有者: "那频率要+10，输入 6 和 8"
拆弹者: [输入 68] [发送]
```

#### 失败场景
- 节奏描述错误（"短短长" vs "短短短长"）
- 忘记确认序列号规则
- 频率偏移计算错误

### 2. 🧩 象形符号键盘 (Hieroglyph Keyboard) ✅ 推荐优先实现

#### 信息分割设计

**拆弹者看到：**
```
┌─────────────────┐
│  ┌───┐ ┌───┐   │
│  │ 👁 │ │ 🌙 │   │  ← 4个象形符号按钮（2x2）
│  └───┘ └───┘   │     符号完全陌生，没有文字标签
│  ┌───┐ ┌───┐   │
│  │ 🐍 │ │ 🔥 │   │
│  └───┘ └───┘   │
│                 │
│  状态: 等待输入  │
└─────────────────┘
```
- 4个完全陌生的符号（眼睛、月亮、蛇、火焰等）
- 没有文字标识，只能用视觉描述
- 按钮按下后无法撤销（必须完成序列）

**手册持有者拥有：**
```
符号识别指南
┌────────────────────────────────────────┐
│ 第一步：确认符号集合                    │
│                                         │
│ 让拆弹者描述4个符号的特征：              │
│ • 眼睛形状 → "👁"                       │
│ • 弯月形状 → "🌙"                       │
│ • 波浪线/蛇形 → "🐍"                    │
│ • 向上火焰 → "🔥"                       │
├────────────────────────────────────────┤
│ 第二步：根据序列号确定点击顺序          │
│                                         │
│ 查序列号末位数字：                       │
│ 0-2: 眼睛 → 蛇 → 月亮 → 火焰            │
│ 3-5: 火焰 → 眼睛 → 月亮 → 蛇            │
│ 6-8: 蛇 → 火焰 → 眼睛 → 月亮            │
│ 9:   月亮 → 蛇 → 火焰 → 眼睛            │
├────────────────────────────────────────┤
│ 第三步：确认按下反馈                    │
│ 每个正确按下会亮绿灯，错误会全红重置     │
└────────────────────────────────────────┘
```

#### 沟通流程
```
拆弹者: "4个按钮，左上像个眼睛，右上像个月亮"
拆弹者: "左下是波浪线像蛇，右上是火焰"
手册持有者: "确认一下，蛇是左下，火焰是右下？"
拆弹者: "对"
手册持有者: [查序列号规则] "末位是3，顺序是火焰→眼睛→月亮→蛇"
手册持有者: "先按右下火焰，然后左上眼睛，右上月亮，左下蛇"
拆弹者: [依次按下]
```

#### 关键设计：符号混淆
- 故意使用容易混淆的符号对：
  - 🌙 (月亮) vs 🌞 (太阳) 
  - 👁 (眼睛) vs 👄 (嘴巴)
  - 🔥 (火) vs 💧 (水)
- 描述不清会导致完全错误的方向

### 3. 🎚️ 滑动拼图密码 (Sliding Cipher)

#### 信息分割设计

**拆弹者看到：**
```
┌─────────────────┐
│  目标序列: A-C-E │  ← 顶部显示需要的序列
│                 │
│  ┌───┬───┬───┐  │
│  │ B │ D │ A │  │  ← 3x3 滑动拼图
│  ├───┼───┼───┤  │     可以上下左右滑动
│  │ C │   │ F │  │     空格在中心
│  ├───┼───┼───┤  │
│  │ G │ H │ E │  │
│  └───┴───┴───┘  │
│                 │
│  [ 确认序列 ]    │  ← 当顶行是A-C-E时按确认
└─────────────────┘
```
- 一个3x3滑动拼图，带一个空格
- 顶部显示目标序列（如 A-C-E）
- 需要让**顶行**拼出目标序列

**手册持有者拥有：**
```
滑动拼图解法指南

注意：拆弹者无法直接滑动单个字母！
每次移动会影响整行或整列。

通用解法步骤：
1. 先问拆弹者："空格在哪个位置？"
2. 再问："目标字母A在哪？"
3. 规划路径将A移到左上角
4. 然后固定A，处理C和E

特殊规则（根据序列号）：
• 序列号有重复数字 → 目标序列是 A-C-E
• 无重复数字 → 目标序列是 B-D-F
• 含数字0 → 目标序列是 G-H-I（底行！不是顶行）
```

#### 沟通复杂度
- 拆弹者需要报告9个格子的当前状态
- 手册持有者需要 mentally solve sliding puzzle
- 指挥拆弹者一步步移动（"把空格移到右边，然后A会掉下去"）
- 容易因方向描述错误（你的左 vs 我的左）而混乱

### 4. 🔀 线路重连模块 (Circuit Rewire)

#### 信息分割设计

**拆弹者看到：**
```
┌─────────────────┐
│  输入端      输出端  │
│  [1] ──┐    ┌── [A] │
│  [2] ──┼────┼── [B] │  ← 6个输入端口（数字编号）
│  [3] ──┤    ├── [C] │  ← 6个输出端口（字母编号）
│  [4] ──┼────┼── [D] │  ← 已有部分连线（彩色）
│  [5] ──┤    ├── [E] │
│  [6] ──┘    └── [F] │
│                 │
│  [  测试连线  ]  │
└─────────────────┘
```
- 左侧6个输入端口（1-6），右侧6个输出端口（A-F）
- 已经有一些随机连线（彩色）
- 需要添加/移除连线使连接正确

**手册持有者拥有：**
```
线路重连规则表

首先询问拆弹者：
"已存在的连线有哪些？输入数字到输出字母"

然后根据序列号查表：

┌────────────────┬─────────────────────────────┐
│ 序列号特征      │ 正确连接规则                 │
├────────────────┼─────────────────────────────┤
│ 末位是奇数      │ 1-A, 2-C, 3-E, 4-B, 5-D, 6-F│
│ 末位是偶数      │ 1-F, 2-D, 3-B, 4-E, 5-C, 6-A│
├────────────────┼─────────────────────────────┤
│ 有重复字母      │ 必须保留原有红线的连接       │
│ 无重复字母      │ 必须断开原有红线的连接       │
└────────────────┴─────────────────────────────┘

注意：拆弹者只能添加/删除连线，不能修改已有连线颜色
```

#### 沟通复杂度
- 需要清晰描述已有连线（"2号连到B是蓝色的线"）
- 手册持有者需要比对规则，找出哪些需要改
- 拆除/添加特定连线需要精确指令

### 5. 📻 无线电调频 (Radio Tuner)

#### 信息分割设计

**拆弹者看到：**
```
┌─────────────────┐
│  当前频率: 103.5 │  ← 数字显示
│                 │
│  [◀────●────▶]  │  ← 滑块，范围 88.0 - 108.0
│                 │
│  信号强度: [░░░] │  ← 信号强度条（实时变化）
│                 │
│  [  锁定  ]      │
│                 │
│  背景噪音: 沙沙声 │
└─────────────────┘
```
- 可以调节 FM 频率（88.0-108.0）
- 信号强度条会随频率变化
- 接近正确频率时能听到微弱的"正确音效"
- 但不知道正确频率是多少

**手册持有者拥有：**
```
无线电频率解码表

首先要求拆弹者报告：
• 当前序列号
• 当前剩余时间（分钟）

计算正确频率：
┌──────────────────────────────────────────┐
│ 基础频率 = 序列号数字之和 × 2 + 88.0      │
│                                          │
│ 调整因子（根据剩余时间）：                │
│ • >3分钟：基础频率 + 0.0                 │
│ • 1-3分钟：基础频率 + 5.0                │
│ • <1分钟：基础频率 + 10.0                │
└──────────────────────────────────────────┘

示例：
序列号 X7K2M9 → 7+2+9 = 18
基础 = 18×2 + 88 = 124 → 超过范围！

如果超过108，则减去20 → 104.0
```

#### 异步合作亮点
- 需要实时报告当前频率和信号强度
- 手册持有者计算后给出目标频率
- 接近目标时拆弹者听到反馈，需要描述（"现在听到一些滴滴声"）
- 手册持有者确认是否锁定

### 6. 🎯 多阶确认按钮 (Multi-Stage Button)

#### 信息分割设计

**拆弹者看到：**
```
┌─────────────────┐
│  当前标签: [停止] │  ← 按钮上的文字会变化
│                 │
│  ┌───────────┐  │
│  │   停止    │  │  ← 大按钮
│  └───────────┘  │
│                 │
│  指示灯: 🟡      │  ← 颜色指示（黄/蓝/红/白）
│                 │
│  计时器: 15s    │  ← 模块自带倒计时
└─────────────────┘
```
- 一个按钮，上面文字会在不同时机变化
- 旁边有指示灯（黄/蓝/红/白）
- 模块自带倒计时（独立于主计时器）
- 不知道何时按、按多久

**手册持有者拥有：**
```
多阶按钮操作手册

第一阶段：确认时机
询问拆弹者：
• "按钮上现在写什么字？"（停止/按住/释放/等待）
• "指示灯是什么颜色？"
• "模块倒计时还剩几秒？"

第二阶段：查表决定操作

┌──────────┬────────┬───────────┬──────────────┐
│ 按钮文字  │ 指示灯 │ 倒计时    │ 操作指令      │
├──────────┼────────┼───────────┼──────────────┤
│ 停止      │ 黄色   │ >5秒      │ 立刻单击      │
│ 停止      │ 黄色   │ ≤5秒      │ 按住3秒后释放 │
│ 按住      │ 蓝色   │ 任意      │ 按住直到变白  │
│ 释放      │ 红色   │ 奇数秒    │ 立刻释放      │
│ 释放      │ 红色   │ 偶数秒    │ 再按住2秒     │
│ 等待      │ 白色   │ ≤3秒      │ 连续点击3次   │
└──────────┴────────┴───────────┴──────────────┘

第三阶段：执行并确认
拆弹者执行指令后报告结果
如果按钮文字变化，回到第一阶段
需要连续正确完成3次才算模块解除
```

#### 沟通复杂度
- 信息量大（文字+颜色+时间）
- 时机非常关键
- 需要快速连续的沟通

## 模块对比矩阵

| 模块 | 信息类型 | 沟通频次 | 错误敏感度 | 推荐优先级 |
|------|---------|---------|-----------|-----------|
| 摩斯电码 | 听觉描述 | 中 | 中 | ⭐⭐⭐⭐⭐ |
| 象形符号 | 视觉描述 | 高 | 高 | ⭐⭐⭐⭐⭐ |

| 线路重连 | 清单核对 | 中 | 中 | ⭐⭐⭐⭐ |
| 无线电调频 | 数值反馈 | 高 | 低 | ⭐⭐⭐⭐ |

## 建议的首批实现

### 第一优先（核心机制验证）
1. **摩斯电码** - 经典KTANE风格，易于理解
2. **象形符号** - 视觉描述的训练

### 第二优先（增加深度）
3. **线路重连** - 逻辑复杂度适中
4. **无线电调频** - 引入数值计算

### 第三优先（挑战模式）
5. **滑动拼图** - 高沟通负担
6. **多阶按钮** - 时间压力极大
