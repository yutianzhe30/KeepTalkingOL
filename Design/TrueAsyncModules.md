# ⏳ 新模块设计提案 - 真·异步合作模式 (True Asynchronous)

> 文档状态：构思中
> 游戏模式：真·异步合作 (回合制 / 留言板式通讯 / 时间冻结)
> 核心机制：**延时指令 + 状态预测 + 批量执行**

---

## 核心设计原则

### 1. 真·异步架构 (True Asynchronous)
与传统的实时语音沟通不同，“真·异步”模式假设拆弹者和手册持有者无法进行实时交流。
时间在沟通期间是**冻结**的，或者通讯本身存在**巨大延迟**（类似通过缓慢的电报或相隔光年的留言板通讯）。

```
┌─────────────────┐       发送状态快照 (耗时)       ┌─────────────────┐
│   拆弹者        │  ───────────────────────►  │  手册持有者      │
│  (游戏客户端)    │                            │  (说明书/Manual) │
│                 │  ◄───────────────────────  │                 │
│ • 冻结时间/拍照   │       发送操作指令 (耗时)       │ • 收到过去的状态 │
│ • 批量录入指令   │                            │ • 预测未来变化   │
│ • 一次性执行     │                            │ • 制定复合操作计划│
└─────────────────┘                            └─────────────────┘
```

### 2. 三大设计支柱

| 支柱 | 说明 | 示例 |
|------|------|------|
| **状态快照** | 拆弹者只能发送静态或历史的模块状态 | "我截取了第10秒的雷达图像" |
| **预测与推演** | 手册持有者必须预测指令到达时模块的状态 | "当你收到这条信息时，指针应该在第三象限" |
| **批处理执行** | 拆弹者收到长指令后，进行一次性输入或编程 | "按顺序输入：上-等待2秒-切红线-左" |

## 新模块提案

### 1. 📇 打孔卡执行器 (Punch Card Executor) ✅ 推荐优先实现

#### 核心机制
编程解谜。拆弹者无法直接操作模块，必须根据手册持有者的指令"编程"，然后一次性执行。

#### 拆弹者看到：
```
┌─────────────────┐
│  初始状态: [X]   │  ← 一个受限的初始状态（如迷宫起点，或特定数列）
│                 │
│  打孔卡槽位 (0/5)│
│  [+][+][+][+][+]│  ← 可插入5条指令
│                 │
│  指令池:        │
│  [位移] [翻转]  │  ← 简单的基础指令
│  [延时] [条件]  │
│                 │
│  [ 批量执行 ]    │  ← 只能按一次！
└─────────────────┘
```
- 拆弹者将当前状态（如迷宫布局、数列）截图或文本发送给手册持有者。
- 拆弹者不能一步一步尝试，必须将整个流程填入打孔卡，然后点击"批量执行"。

#### 手册持有者拥有：
- 详细的指令逻辑组合规则。
- 只有手册持有者知道"终点"或"正确结果"是什么。
- **沟通流程：**
  - 拆弹者："初始数列是 4-1-8-3，有位移和翻转指令。"
  - 手册持有者：（查表发现需要将数列变为递增）"指令序列应该是：翻转，右移，翻转，左移。你一次性录入这4个指令。"
  - 拆弹者录入并执行。如果中间有一步错，整个结果就会错并触发失误。

---

### 2. 🪐 轨道预测仪 (Orbital Predictor)

#### 核心机制
物理/时机预测。时间在发送消息时会流逝，手册持有者必须计算指令到达或拆弹者执行时的"未来状态"。

#### 拆弹者看到：
```
┌─────────────────┐
│  卫星: 🔵 (公转) │  ← 匀速绕中心旋转
│  目标: 🎯        │  ← 固定的目标点
│                 │
│  延迟计时: 15s   │  ← 通讯延迟（模拟）
│                 │
│  [发射探测器]    │  ← 按下后会有一段飞行时间
└─────────────────┘
```
- 有一个以已知速度运动的元素。
- 拆弹者向手册持有者报告："当前卫星在12点钟方向，公转周期是20秒。"

#### 手册持有者拥有：
- 复杂的星历表和发射窗口计算公式。
- 手册持有者需要计算出完美的发射时机，但这面临**双重延迟**（拆弹者读消息的时间 + 模块本身的响应时间）。
- **沟通流程：**
  - 手册持有者："卫星每20秒一圈。你需要它在3点钟方向击中目标。探测器飞行需要5秒。"
  - 手册持有者："所以，当卫星走到**12点钟方向**时，立刻按下发射键！"

---

### 3. 📦 量子状态锁 (Quantum State Lock)

#### 核心机制
观测即改变。拆弹者每次向手册持有者报告状态（观测），都会导致状态发生确定性或半确定性的"坍缩"。

#### 拆弹者看到：
```
┌─────────────────┐
│  当前状态: 隐匿  │
│                 │
│  [ 进行观测 ]    │  ← 点击后显示短暂的当前状态，但同时改变状态！
│                 │
│  输入序列: _ _ _ │
│  [1] [2] [3] [4]│
└─────────────────┘
```
- 初始状态不可见。
- 拆弹者点击"进行观测"，看到诸如"红色-波形-高频"，并报告给手册。
- **关键**：观测这一动作会导致状态按特定规律演化（例如，每次观测，颜色顺时针变一次）。

#### 手册持有者拥有：
- 状态演化状态机（State Machine）。
- 手册持有者需要根据拆弹者的**第一次观测结果**，推演出**下一次他不观测时的状态**。
- **沟通流程：**
  - 拆弹者："我观测了，是红色。"
  - 手册持有者："红色观测后会坍缩成蓝色。解除蓝色的密码是 3-1-4。"
  - 手册持有者："**千万不要再观测了！**直接盲输 3-1-4！如果你再观测，它就会变成绿色！"

---

### 4. 📜 预言家信标 (Prophet's Beacon)

#### 核心机制
时间胶囊的反向应用。手册持有者给出一系列"预言"（条件触发指令），拆弹者像查阅备忘录一样，在特定事件发生时执行。

#### 拆弹者看到：
```
┌─────────────────┐
│  传感器网络      │
│  温度: 45℃       │  ← 各种环境数值在缓慢/随机波动
│  湿度: 60%       │
│  气压: 101 kPa   │
│                 │
│  阀门A [开/关]   │
│  阀门B [开/关]   │
└─────────────────┘
```
- 数值在炸弹计时期间不断变化。

#### 手册持有者拥有：
- 应急操作指南。由于"真·异步"无法实时指挥，手册持有者必须提前下达**批处理条件指令**。
- **沟通流程：**
  - 手册持有者发出一大段留言（指令集）：
    - "如果温度超过 50℃，立刻打开阀门A。"
    - "如果湿度降到 40% 以下，关闭所有阀门。"
    - "当气压和温度的百位数相同时，保持阀门B开启5秒。"
  - 拆弹者将这段留言视为"本地缓存手册"，在接下来的游戏过程中独立监控并在触发条件时执行，不再与手册持有者确认。

---

## 异步协作体验总结

这种"真·异步"设计极大改变了传统KTANE的体验：
1. **降低了语音沟通的混乱度**：从七嘴八舌的实时呼喊，变成了写小作文和发送电报。
2. **提高了逻辑推理的纯度**：减少了反应力要求，增加了空间计算和状态机推演。
3. **延迟即玩法**：通讯延迟不再是网络不佳的缺点，而是游戏核心机制的一部分。
