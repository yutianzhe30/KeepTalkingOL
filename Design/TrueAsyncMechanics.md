# ⏳ 真·异步合作模式设计 (True Asynchronous Mode)

> 文档状态：概念验证 (Proof of Concept)
> 游戏模式：回合制/消息传递 (Message Passing)
> 核心机制：时间冻结 + 预测性指令 + 延迟反馈

---

## 核心设计理念

传统的《Keep Talking and Nobody Explodes》及类似游戏（如我们当前的`ModuleDesigns_CoOp.md`）通常依赖**同步语音通信**。
"真·异步"（True Async）模式旨在打破这一限制，允许两名玩家在**不同时间、不同地点**进行合作解谜，无需同时在线。

### 为什么要做真异步？
1. **匹配便捷**：不再受限于两人必须同时有空（如双人成行）。
2. **沉思空间**：给手册持有者充足的时间查阅和计算，减少了同步沟通的即时压力。
3. **策略深度**：从"操作反应"转向"策略规划"和"逻辑预测"。

---

## 核心机制设计

### 1. 时间冻结 (Time Freeze)
- 游戏**没有实时倒计时**，或者倒计时在玩家未操作时是冻结的。
- 时间以"回合"（Turns）或"操作步数"（Actions）来计算。
- 当拆弹者打开游戏查看炸弹时，时间处于静止状态。

### 2. 消息传递系统 (Message Passing)
- 两人通过游戏内建的**类似邮件/短信的系统**进行沟通。
- 每次发送消息可能需要消耗"时间"或"电力"。
- **字数限制/词汇表限制**：为了增加难度，可以限制每条消息的长度，或者只允许使用特定的短语组合（类似《黑暗之魂》的建言系统）。

### 3. 预测性指令 (Predictive Instructions)
这是真异步模式的灵魂机制：
- 手册持有者不能像同步模式那样"看一步走一步"。
- 他们必须给出**条件分支指令（If-Then-Else）**。

#### 示例：传统同步 vs 真异步

**传统同步：**
> 拆弹者："我看到一条红线和一条蓝线。"
> 手册："好的，你先剪红线。"
> 拆弹者："剪了，现在灯变绿了。"
> 手册："那现在剪蓝线。"

**真异步：**
> 拆弹者发消息："有红蓝两线，当前灯是黄色的。"
> 手册回复消息："如果剪红线后灯变绿，就继续剪蓝线；如果剪红线后灯变红，千万别剪蓝线，先按住旁边的按钮3秒。"

### 4. 操作队列与延迟反馈 (Action Queue & Delayed Feedback)
- 拆弹者可以将一系列操作排入队列（Action Queue）。
- 点击"执行"后，系统一次性演算这些操作的结果。
- 结果以**日志（Log）**的形式反馈给拆弹者，拆弹者再将日志发送给手册持有者。

## 专属真异步模块提案

普通模块由于需要频繁交互，不太适合真异步。以下是专为真异步设计的模块：

### 1. 🔀 条件逻辑锁 (Conditional Logic Locks)

#### 视觉设计
```text
┌───────────────────────────────┐
│ [指示灯] 🟡                     │
│                               │
│  变量区:                       │
│  [A=5]  [B=2]  [C=黄]          │
│                               │
│  操作区:                       │
│  [+1A] [-1B] [反转C]            │
│  [提交状态]                    │
└───────────────────────────────┘
```

#### 机制说明
- 模块包含几个变量（A, B, C）和几个操作按钮。
- **拆弹者**看到当前的变量初始状态。
- **手册持有者**拥有目标状态的规则表（例如：若序列号为偶数，则最终要求 A>B 且 C=绿）。
- 但是！每次点击操作按钮，变量的变化规律只有手册持有者知道，且可能是非线性的（例如：点击 [+1A] 会让 A+1，但如果此时 C 是黄色，B 也会跟着 -1）。

#### 异步交互流程
1. **拆弹者发送**："初始：A=5, B=2, C=黄。序列号尾数8。"
2. **手册持有者计算**："目标是A>B且C=绿。操作[反转C]会让C变绿但A清零... 我需要给他一个完整的操作序列。"
3. **手册持有者发送指令**："执行顺序：1. [-1B] 2. [反转C] 3. [+1A] 连续点五次 4. [提交状态]"
4. **拆弹者按顺序无脑执行**，如果不发生意外则一次解开。

### 2. 🗺️ 盲眼探路者 (Blind Pathfinder)

#### 视觉设计
```text
┌───────────────────────────────┐
│           [北]                │
│       ┌─────────┐             │
│  [西] │    ●    │ [东]        │
│       └─────────┘             │
│           [南]                │
│                               │
│  步数剩余: 5                   │
│  日志: 暂无                    │
└───────────────────────────────┘
```

#### 机制说明
- 一个不可见的迷宫，拆弹者只能看到自己在中心（●）。
- **手册持有者**有一张完整的迷宫地图，包含陷阱和终点。
- 但地图在每局开始时会发生**随机旋转或镜像**（参考 `OriginalModules.md` 中的镜像错位）。

#### 异步交互流程
1. **探测阶段**：拆弹者只有5步的视野探测能力。
   - 拆弹者发送："我向北试探了1步，撞墙；向东试探了1步，有水声。"
2. **定位阶段**：手册持有者根据地形特征确定地图的方向和拆弹者的位置。
   - 手册持有者发送："确认了，水声在你的东边，说明地图是逆时针转了90度。从现在的位置开始，指令序列为：西2步，南3步，东1步。不要有任何偏差。"
3. **执行阶段**：拆弹者将序列输入并执行。

---

### 3. 🧬 基因排序机 (Genetic Sequencer)

#### 机制说明
- 拆弹者看到一段初始序列（如 `ATCGGCTA`）。
- 模块每经过一个"回合"（或收到一次消息），序列会根据未知的规则发生**变异**。
- 手册持有者拥有变异规则表和目标序列。

#### 异步交互流程
- 这个模块强调**时间成本**。
- 手册持有者不能只是给出简单的操作，必须预测拆弹者在收到消息时，序列已经变异成了什么样子。
- 手册回复："当你收到这条消息时，序列应该变成了 `TAAGC...`，如果是这样，请立刻按下[截断]按钮；如果不是，请回复当前的序列，我们再来过。"

## 游戏循环总结 (Game Loop)

1. **登录与快照**：拆弹者登录游戏，炸弹状态被"冻结"并生成一个当前状态快照。
2. **汇报**：拆弹者通过游戏内信使向手册持有者发送各个模块的状态描述。
3. **离线处理**：手册持有者收到通知（比如手机推送），在现实中花时间查阅手册、计算逻辑、推演可能性。
4. **下达指令**：手册持有者编写带有条件判断的预测性指令发送回游戏。
5. **执行与结算**：拆弹者登录，阅读指令，排队执行操作。系统结算这一个回合的结果，若未爆炸且未全解，则进入下一回合。
