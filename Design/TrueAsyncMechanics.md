# 🎮 真·异步合作模式设计提案 (True Asynchronous Co-Op)

> 文档状态：设计草案
> 游戏模式：真·异步双人合作 (True Async Co-Op)
> 核心概念："留言式"沟通、时间冻结、预判指令 (Message-passing, Time freezes, Predictive instructions)

---

## 核心设计理念 (Core Concept)

传统的 "Keep Talking and Nobody Explodes" (KTANE) 是"伪异步"（即同步合作）—— 两个玩家必须同时在线并实时语音沟通。
"真·异步"模式旨在打破这一限制，允许两名玩家**不在同一时间进行游戏**，通过游戏内的异步机制完成拆弹。

### 1. 异步机制架构

```
┌──────────────────┐               ┌──────────────────┐
│   玩家 A (勘测员)  │  异步留言/档案  │   玩家 B (解弹员)  │
│  (游戏第一阶段)    │ ──────────────► │  (游戏第二阶段)    │
│                  │               │                  │
│ • 查看炸弹配置     │               │ • 阅读 A 的留言    │
│ • 记录模块状态     │               │ • 查阅拆弹手册     │
│ • 预判可能的危险   │               │ • 制定拆弹步骤     │
│ • 提交勘测报告     │               │ • 实际操作拆除     │
└──────────────────┘               └──────────────────┘
```

或者采用**回合制 (Turn-based)** 架构：
- **回合 1 (A)**: A 打开游戏，看到模块状态，给 B 留言（如"线序是红蓝绿"，"序列号是X7..."），然后冻结时间。
- **回合 2 (B)**: B 收到通知上线，查手册解题，给 A 回复指令（如"剪第二根蓝线"）。
- **回合 3 (A)**: A 上线执行 B 的指令，如果正确，进入下一个模块/步骤。

### 2. 三大设计支柱

| 支柱 | 说明 | 示例 |
|------|------|------|
| **时间冻结** | 玩家可以主动冻结炸弹计时，以思考或等待另一方。 | 冻结期间无法操作模块，但可以输入留言。 |
| **受限的通信** | 不使用外部聊天软件，而是通过游戏内的"终端留言板"。 | 有字数限制或只能使用预设词条。 |
| **预判指令** | 由于不是实时沟通，给出的指令需要涵盖所有可能性（If-Else 逻辑）。 | "如果按了按钮灯变红，就等3秒再按；如果变绿，就马上按。" |

## 新模块设计：异步专用 (Async-Specific Modules)

传统模块通常需要实时反馈，以下模块专为"预判"和"回合制"设计：

### 1. 🔀 状态机按钮 (State Machine Button)

**拆弹者看到：**
- 一个按钮。
- 一个小屏幕显示当前状态编号（如 "State: A"）。
- 操作按钮后，状态会变成未知的 B 或 C。

**手册持有者拥有：**
- 一张状态转换图（State Machine Graph）。

**异步沟通方式：**
- **手册持有者留言**：
  "你在 State A，按一次。
  如果变成 State B，再按两次；
  如果变成 State C，等5秒再按一次。"
- **拆弹者执行**：根据收到的 "If-Else" 剧本，连续完成多次操作。
- **挑战**：手册持有者需要穷举所有分支，如果剧本漏了某个分支，拆弹者就会卡住（被迫消耗回合数去询问）。

### 2. 🔮 预判迷宫 (Predictive Maze)

**拆弹者看到：**
- 迷宫的起点和部分墙壁，但有迷雾遮挡远方。

**手册持有者拥有：**
- 完整的迷宫地图，但不知道起点在哪里（或者有多个可能的起点）。

**异步沟通方式：**
- **拆弹者留言**："我在一个死胡同，左边是墙，右边是墙，前面有路。走了两步后遇到分叉（左右）。"
- **手册持有者留言**："你可能在坐标 (2,4) 或者 (7,8)。
  如果是 (2,4)，向左走会看到一个红点。
  如果是 (7,8)，向右走会看到一个蓝点。
  看到红点就一直往前，看到蓝点就退回来向左。"

### 3. 🧪 化学方程式 (Formula Synthesis)

**拆弹者看到：**
- 几个烧杯，里面有不同颜色的液体（例如：红 30ml, 蓝 50ml, 绿 20ml）。
- 没有配方。

**手册持有者拥有：**
- 复杂的化学配方表，取决于液体的初始毫升数。

**异步沟通方式：**
- **拆弹者留言**："红 30, 蓝 50, 绿 20。"
- **手册持有者留言（计算耗时较长）**：
  "首先把 10ml 红倒入蓝中。
  然后看混合后的颜色，如果是紫色，就把绿的全倒进去。
  如果是深蓝，就把剩下的红倒掉。"
- **挑战**：这是一个典型的多步计算，适合异步模式下让手册持有者慢慢算，不用有实时的压力，但一旦指令出错后果很严重。

### 4. ⏳ 延迟引信 (Delayed Detonator)

**特性：**
- 操作后不会立刻反馈成功或失败。
- 例如：输入一组密码后，模块显示 "Processing..." 并在 2 个真实小时后才显示结果。
- **意义**：强制游戏进入异步等待期。玩家可以在这2小时内下线。

## 异步沟通系统设计 (Async Messaging System)

为了让异步玩法成立，游戏内需要内置一个通信终端。

### "传真机" (The Fax Machine) UI 设计
```
┌─────────────────────────────────────────┐
│ [收到的指令 - 来自 玩家 B]                │
│ 1. 接线模块：剪掉带有红条纹的线。           │
│ 2. 摩斯模块：如果听到三短，输入频率 45。    │
│    如果是两短一长，输入频率 68。          │
│                                         │
│ --------------------------------------- │
│ [回复 - 给 玩家 B]                       │
│ 接线已剪。摩斯模块其实是"长长短"，怎么办？  │
│ 另外这里有一个新模块，四个图标分别是：      │
│ 眼睛、月亮、火、水。顺序是啥？             │
│                                         │
│                                         │
│ [ 发送并冻结时间 (结束回合) ]             │
└─────────────────────────────────────────┘
```

### 限制机制 (Constraints for Fun)
为了防止玩家直接写一篇长篇大论完全破解，可以加入以下限制：
1. **电报模式 (Telegram Mode)**: 每次留言最多 50 个字符。
2. **符号表意 (Emoji Mode)**: 只能用特定的预设符号和图标进行交流，不能打字。
3. **延迟送达 (Delayed Delivery)**: 消息发送后，对方需要等 1 分钟（或者游戏内的时间单位）才能看到，增加沟通成本。

## 游戏循环流程 (Game Loop)

1. **新建战局 (Create Session)**: 玩家 A 启动一个炸弹局。
2. **勘测阶段 (Scouting Phase)**: A 有 2 分钟时间查看炸弹并记录（或者时间静止）。
3. **发包 (Send Packet)**: A 将战局数据和第一条留言发给服务器（或通过代码复制给 B）。
4. **解题阶段 (Solving Phase)**: B 收到包（代码），查阅手册，撰写拆弹指令。
5. **回传包 (Return Packet)**: B 将指令发回给 A。
6. **执行阶段 (Execution Phase)**: A 根据指令执行操作。
7. 重复 3-6 直到拆除或爆炸。
