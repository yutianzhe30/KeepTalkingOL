# 🎮 新模块设计提案 - 真·异步合作模式 (True Asynchronous)

> 文档状态：审阅中
> 游戏模式：真·异步双人合作（回合制/留言式）
> 核心机制：**时间分离 + 指令预判 + 有限交流**

---

## 核心设计原则

### 1. 时间分离架构
```
┌─────────────────┐          延迟/限制通信         ┌─────────────────┐
│   拆弹者        │  ◄──────────────────────►  │  专家(手册持有者) │
│  (游戏客户端)    │    （回合制 / 留言板）      │  (说明书/终端)   │
│                 │                            │                 │
│ • 冻结时间拍照   │                            │ • 阅读过期的快照 │
│ • 收到延迟指令   │                            │ • 预判模块变化   │
│ • 批量执行操作   │                            │ • 编写序列指令   │
└─────────────────┘                            └─────────────────┘
```

### 2. 真异步的挑战

与实时语音不同，真异步去除了"即时反馈"。
专家必须说："按A，如果灯亮了就按B，否则按C"。
拆弹者必须说："这是我5秒前的状态截屏，现在它可能已经变了"。

## 新机制提案

### 1. 📸 拍立得快照 (Polaroid Snapshot)

#### 机制描述
拆弹者不能用语音描述，而是将视角的模块"拍照"。照片会有一定的"显影时间"或"传送延迟"才能到达专家端。

#### 专家视角
- 收到一张带有时间戳的照片（例如：`T-04:30 拍摄`）。
- 照片可能是局部的、模糊的，或者带有一点反光干扰。
- 专家可以在照片上圈画，加上文字说明（如：`先剪这条(红)`），然后把照片"传回"给拆弹者。

#### 异步冲突
- 专家发回指令时，炸弹的时间已经过去了30秒。如果模块的状态是随时间变化的（例如定时改变的LED灯），专家必须在指令中加入时间条件：`当时间尾数是偶数时再剪`。

---

### 2. 📜 预编程指令队列 (Instruction Queue)

#### 机制描述
针对需要高频操作的模块（如迷宫、平衡），拆弹者无法等待专家的即时导航。

#### 专家视角
专家在自己的界面上编写一串完整的宏指令，然后一次性发送给拆弹者。
例如：`[前] [前] [左] [等待2秒] [右] [确认]`

#### 拆弹者视角
- 拆弹者收到指令带，点击[执行]，模块会按照指令自动运行。
- 如果中途出错（撞墙），操作会立刻中断并引发惩罚。
- 拆弹者需要根据失败的位置，给专家发送反馈：`在第3步[左]的时候撞墙了`。

---

### 3. ⏳ 延迟信使 (Delayed Messenger)

#### 机制描述
双方只能通过一个老式的电报机/短信界面交流。
每条消息都有**发送字数限制**和**到达延迟**（例如10秒）。

#### 异步挑战
- **并发冲突**：专家正在打字发送"不要剪红线"，同时拆弹者发来了"我已经剪了红线，接下来呢？"。两条消息在空中交汇，产生喜剧/悲剧效果。
- 玩家需要发明简略的沟通语言来节省字数和时间。如：`S3=红?` (序列号第3个是红色吗？)。

---

### 4. 🔮 薛定谔的状态 (Schrödinger's State)

#### 机制描述
针对那些随时间自动变化的模块，拆弹者发送状态后，该状态在专家端是"不确定"的。

#### 设计示例：转盘锁
- 拆弹者看到一个有3个插槽的转盘，每10秒转动一格。
- 拆弹者发送信息："现在12点方向是红色插槽"。
- 专家收到信息时，已经过去了15秒。专家必须自己推算：`过了15秒，转盘转了1格半，现在12点方向应该是空的，红色在4点方向`。
- 专家的指令必须是：`当红色转到8点钟方向时，插入钥匙`。

## 真异步专用模块设计

### 1. 🗄️ 档案分类机 (Filing System)

- **拆弹者**看到源源不断传送过来的文件（带有各种符号和颜色）。
- 拆弹者每次只能挑出3个文件，拍成照片发给专家。
- **专家**需要查阅厚厚的档案分类规则，然后回复分类指令：`文件A放左边，文件B销毁，文件C放右边`。
- 因为有延迟，拆弹者在等待回复时，必须先处理其他文件，或者眼睁睁看着文件堆积（堆满则爆炸）。

### 2. 📡 轨道卫星预测 (Orbital Prediction)

- **拆弹者**屏幕显示一个雷达，上面有几个光点以特定轨道运行。
- 拆弹者点击[记录]，雷达会生成一张包含光点位置和速度矢量的打孔纸带，发送给专家。
- **专家**有一本星历表。专家根据纸带上的初始状态，预测30秒后光点的位置，并向拆弹者发送拦截指令坐标。
- **拆弹者**在指定坐标设置拦截网，等待光点自行撞上。

## 游戏体验总结

真异步合作模式将 KTANE 的"沟通混乱"转化为了"时空错位的策略规划"。
- 它对网络延迟的要求极低（甚至可以作为异步网页游戏来玩）。
- 它鼓励玩家建立自己的 SOP（标准作业程序）和密语。
- 失败往往来源于"预判了你的预判"，产生独特的喜剧效果。
