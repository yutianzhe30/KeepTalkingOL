# ⏳ 真·异步合作模式设计提案 (True Asynchronous Co-op)

> 文档状态：概念验证中
> 游戏模式：纯异步（回合制/消息传递/高延迟环境）
> 核心挑战：**如何在无法实时语音的情况下，保持拆弹的紧张感和合作深度？**

---

## 核心设计理念

传统的 KTANE 依赖极高频的实时双向沟通（"我看到一个红色的按钮"，"上面有什么字？"）。
在**真·异步**模式下，我们假设玩家之间存在以下限制：
1. **高延迟或回合制**：每次信息传递有几秒到几小时的延迟（例如通过邮件、聊天软件传纸条）。
2. **带宽受限**：不能发长视频，可能只能发固定格式的短文本或状态码。
3. **状态脱节**：手册持有者给出指令时，拆弹者的游戏状态可能已经发生了变化。

因此，谜题设计必须从**"实时反应"**转向**"预判、打包信息、批处理执行"**。

---

## 异步专属机制

### 机制 A: 时停信标 (Time-Freeze Beacon)
- **概念**：由于是异步，拆弹者在遇到复杂模块时，可以按下"时停信标"，冻结该模块的状态和局部倒计时。
- **代价**：时停期间，炸弹的**全局计时器仍会缓慢流逝**（或增加一定的时间惩罚），迫使玩家不能无限期挂机。
- **信息打包**：时停后，模块会生成一串**状态代码**（如 `A7-F9-K2`），拆弹者将此代码发送给手册持有者。
- **批量指令**：手册持有者解析代码后，计算出完整的解题步骤，一次性发送给拆弹者（如 "按顺序剪 1、3、4，然后按红钮"）。拆弹者解除时停并立即执行。

### 机制 B: 预测指令集 (Predictive Instruction Sets)
- **概念**：模块的状态是可预测但随时间变化的（如一个按规律变色的灯阵）。
- **异步配合**：拆弹者描述初始状态和变化规律，手册持有者计算出未来某个特定时间点的状态，并给出**附带时间条件的指令**。
- **示例**："当全局计时器尾数为 5 时，剪断蓝线。如果不成功，等尾数变 0 时再按黄钮。"

## 新模块提案（真异步特化）

### 1. 🖨️ 穿孔纸带机 (Punched Tape Reader)

#### 视觉设计
```
┌─────────────────┐
│  [提取当前纸带]   │  ← 按钮
│                 │
│  输出槽:         │
│  [○●○○●●○]      │  ← 一条包含孔洞的纸带（仅显示一次）
│                 │
│  输入槽:         │
│  [ ][ ][ ][ ]   │  ← 需要填入 4 个孔洞图案
│                 │
│  [  执行打孔  ]  │
└─────────────────┘
```

#### 异步玩法
- **拆弹者**点击提取，获得一条状态纸带（如黑白圆点序列）。
- **拆弹者**将这串序列（或截图）发给手册持有者。
- **手册持有者**拥有一台虚拟的"解密机"（或复杂的对照表），输入原始序列，经过几步转换，得出需要的"解锁孔洞图案"。
- **手册持有者**将这 4 个图案发送回拆弹者。
- **拆弹者**输入并执行。在此期间，模块处于静态，不需要实时反馈。

### 2. 📡 轨道卫星校准 (Orbital Satellite Calibration)

#### 视觉设计
```
┌─────────────────┐
│ 卫星坐标: X=45 Y=12│
│ 轨道周期: 30s    │
│                 │
│ [ 预设发射序列 ]  │
│ 1: 延迟 __ 秒 发射│
│ 2: 延迟 __ 秒 发射│
│ 3: 延迟 __ 秒 发射│
│                 │
│ [ 开始执行序列 ]  │
└─────────────────┘
```

#### 异步玩法
- **核心机制**：拆弹者需要准确击中轨道上的卫星，但不能手动瞄准，只能**预先写好代码**。
- **拆弹者**读取卫星的当前坐标和轨道周期，发送给手册持有者。
- **手册持有者**根据手册上的公式，计算出最佳的发射时间间隔（例如：第一发等 3 秒，第二发等 8 秒，第三发等 12 秒）。
- **手册持有者**将计算好的时间序列发给拆弹者。
- **拆弹者**将数字填入模块，点击"开始执行"。模块会自动按照设定的时间差发射，如果计算正确则解开。
- **优点**：完美适应异步，玩家在交流"算法"，机器负责"实时执行"。

### 3. 📦 薛定谔的包裹 (Schrödinger's Container)

#### 视觉设计
```
┌─────────────────┐
│  包裹 ID: #9942 │
│                 │
│  [  扫描包裹  ]  │  ← 按钮，点击后生成一段 Base64 乱码
│                 │
│  密码锁:         │
│  [ 0 ] [ 0 ] [ 0 ]│
│                 │
│  [  尝试开锁  ]  │
└─────────────────┘
```

#### 异步玩法
- **拆弹者**只能看到包裹 ID 和一段扫描生成的乱码（如 `aGVsbG8=`）。
- **拆弹者**将这段长代码直接复制/发送给手册持有者。
- **手册持有者**需要在游戏外的网页工具（或自带的解码小游戏）中输入这段代码，像解密 ARG（另类实境游戏）一样，还原出包裹里"到底装了什么"以及密码是多少。
- **手册持有者**将最终的 3 位密码发回给拆弹者。
- **变体**：有时解密出的内容是一段音频，手册持有者听完后告诉拆弹者密码。

### 4. 🧭 盲人领航员 (Blind Navigator)

#### 视觉设计
```
┌─────────────────┐
│   起点 [S]       │
│                 │
│  [上传移动脚本]  │  ← 输入框
│   _ _ _ _ _ _   │
│                 │
│  [  运行脚本  ]  │
└─────────────────┘
```

#### 异步玩法
- **拆弹者**处于一个完全看不见障碍物的迷宫中，只知道自己在起点，终点未知。
- **手册持有者**拥有整个迷宫的地图。
- **异步配合**：
  - 手册持有者规划出一条从头到尾的完整路线（如：北 北 东 东 南 东）。
  - 手册持有者将这段**指令脚本**发给拆弹者。
  - 拆弹者将脚本输入模块并点击运行。
  - 光点开始按脚本自动移动。如果撞墙，光点会回到起点，并告诉拆弹者"在第 3 步撞墙了"。
  - 拆弹者反馈错误位置，手册持有者修改脚本后再次发送。

## 游戏流程适配建议

为了支持真异步，游戏大厅或基础系统需要做以下调整：

1. **回合制通信系统**：内置一个类似短信/电报的 UI，限制字数或发送频率，强制玩家精简信息。
2. **长日照模式 (Long-duration Bomb)**：炸弹的总时限不再是 5 分钟，而是 24 小时甚至 7 天。每天玩家花几分钟上线传递一次信息。
3. **离线进展**：即使拆弹者下线，炸弹的倒计时仍在继续，增加真实世界的压迫感。
