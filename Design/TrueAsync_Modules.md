# ⏳ 真·异步合作模块设计 (True Asynchronous Modules)

> 游戏模式：真·异步合作（回合制/消息传递/时间冻结/预测指令）
> 核心机制：**状态快照 + 预测推演 + 延迟执行**
> 灵感：探索不同于实时语音沟通的"回合制"《Keep Talking and Nobody Explodes》体验。

---

## 核心设计原则

### 1. 时间冻结与回合传递
游戏不再是完全实时的。当拆弹者遇到特定模块时，时间可以"局部冻结"（或模块内部时间线独立）。拆弹者将当前状态打包成"消息"发送给手册持有者。
手册持有者在自己的时间线上分析，生成"指令序列"发回给拆弹者。
拆弹者收到后，一键执行指令，观察结果。

### 2. 预测性指令
手册持有者不能仅给出"下一步"指令，而是必须预测系统在连续操作下的状态变化，给出一整套"程序化指令"。如果中间某一步预测错误，后续指令将全部偏离导致失误。

## 新模块提案

### 1. 🤖 预测漫游者 (Predictive Rover)

#### 核心机制
拆弹者只能看到一个静态的"初始快照"，手册持有者必须编写一段完整的"移动程序"，发送给拆弹者一键运行。

#### 信息分割设计

**拆弹者看到（状态快照）：**
```
┌─────────────────┐
│  快照编号: #A72  │
│                 │
│  ┌───┬───┬───┐  │
│  │ R │   │ ⚙️ │  │  R = 漫游者 (面朝右)
│  ├───┼───┼───┤  │  ⚙️ = 目标齿轮
│  │ ⚡ │ █ │   │  │  █ = 障碍物
│  ├───┼───┼───┤  │  ⚡ = 激光陷阱（当前激活）
│  │   │ 🔘 │   │  │  🔘 = 陷阱开关
│  └───┴───┴───┘  │
│                 │
│ [等待接收指令序列] │
└─────────────────┘
```
- 拆弹者能看到网格地图的初始状态（漫游者位置、陷阱、开关、目标）。
- 拆弹者**不能**一步一步操作漫游者。
- 拆弹者必须将地图布局通过文字/代码描述发送给手册持有者（例如："3x3地图，R在左上朝右，目标右上，左中激光..."）。

**手册持有者拥有（规则手册与编程器）：**
```
漫游者编程手册

规则：
1. 漫游者每次移动1格，或原地转向。
2. 🔘 开关被踩下时，⚡ 激光陷阱的状态会反转（激活↔关闭）。
3. 必须在经过⚙️时将其收集，并在最后停留在安全区域。

可用指令：
[F] 前进一格
[R] 右转90度
[L] 左转90度
[W] 等待一个时钟周期（某些动态陷阱需要）
```

#### 沟通与执行流程
1. **快照传递**：拆弹者向手册持有者描述地图初始状态。
2. **预测推演**：手册持有者在脑内（或草稿纸上）推演路线：
   - 如果直接去目标，会被激光挡住。
   - 必须先去踩开关。
   - 路径推演：前进(F)撞墙? 不，先右转(R) -> 前进(F)踩开关 -> 激光关闭 -> 后退? 没有后退指令，需右转两次(R,R) -> 前进(F) -> 左转(L) -> 前进(F) -> 前进(F)到达目标。
3. **指令传递**：手册持有者将完整指令序列（如 `R-F-R-R-F-L-F-F`）发送给拆弹者。
4. **验证执行**：拆弹者输入该序列，点击"运行"。漫游者自动按序列移动，成功则模块解除，撞墙或触碰激光则失误。

### 2. 🎛️ 时序排序器 (Temporal Sequencer)

#### 核心机制
系统状态在未来的几个"时间片"内会发生预定的变化。拆弹者知道未来的变化，手册持有者知道操作的规则。两人必须合作决定在哪个时间片执行哪个操作。

#### 信息分割设计

**拆弹者看到（未来状态预测）：**
```
┌─────────────────┐
│  时间轴预测      │
│                 │
│  T=1: 🔴阀门开启 │
│  T=2: ⚡电压升高 │
│  T=3: 🔵阀门开启 │
│  T=4: ⚡电压恢复 │
│  T=5: 系统重置   │
│                 │
│  操作队列(空)    │
│  [+][+][+][+]   │
└─────────────────┘
```
- 拆弹者可以看到未来5个时间片（T=1到T=5）系统的自然变化。
- 拆弹者需要在下方的空槽中填入4个可用操作（A, B, C, D），为它们分配执行时机。

**手册持有者拥有（操作依赖规则）：**
```
时序操作安全手册

操作 A、B、C、D 必须全部执行，且遵循以下约束：
1. 操作 A 必须在 🔴阀门开启 的状态下执行。
2. 操作 B 必须在操作 A 之后执行。
3. 操作 C 绝对不能在 ⚡电压升高 时执行，否则触发短路。
4. 操作 D 必须在 🔵阀门开启 之前执行。
```

#### 沟通与执行流程
1. **状态传递**：拆弹者将未来的环境变化时间轴（T1~T5）发送给手册持有者。
2. **时序排布**：手册持有者根据规则推导执行序列：
   - A必须在 🔴阀门开启（T=1）或之后仍开启时执行。假设T1执行A。
   - C不能在 ⚡电压升高（T=2和T=3）执行。
   - D必须在 🔵阀门开启（T=3）之前执行。所以D必须在T1或T2执行。
   - 推理结果：T1执行A，T2执行D，T3不操作/执行B，T4执行C...（需完整推理）。
3. **指令下达**：手册持有者发回确定的操作排布表："T1填A，T2填D，T3空，T4填B，T5填C"。
4. **一键结算**：拆弹者填入操作序列，点击"模拟运行"。系统推演时间轴，若没有违背规则且全部执行，则模块解除。

### 真·异步模式设计的优势

1. **消除网络延迟影响**：完全的回合制交流，网络卡顿不影响解谜体验，适合聊天软件/留言板等极其异步的媒介。
2. **降低反应力门槛，提高逻辑上限**：没有实时倒计时的压迫感，转而追求深度逻辑推理和编程思维。
3. **消除沟通中的"重试"成本**：强调"深思熟虑后的一次性提交"，只要推理正确就能一次过。
