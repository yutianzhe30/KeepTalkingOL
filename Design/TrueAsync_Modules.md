# ⏱️ 纯异步模式模块设计 (True Asynchronous Modules)

> 文档状态：设计草案
> 核心目标：探索 "真·异步"（回合制/消息传递）机制，强调指令的延迟性、预判和自动化

---

## 真·异步模式核心理念

传统的《Keep Talking and Nobody Explodes》及类似游戏通常基于**实时语音沟通**。而我们的"真·异步"模式，旨在打破这种实时性，探索以下机制：

1. **指令延迟 (Delay)**：手册持有者发送的指令不会立刻生效，或者拆弹者的操作反馈需要一定时间才能传达给手册持有者。
2. **预判式指令 (Predictive Execution)**：拆弹者需要根据一系列预先设定好的步骤自动执行，而手册持有者必须提前推演出未来的状态。
3. **宏操作/编程化 (Macro/Automation)**：将单次的交流转化为对一段行为逻辑的沟通。

以下是针对此模式的两个原创模块提案。

---

## 模块一：🤖 自动化流水线 (Automated Assembly Line)

### 核心体验
拆弹者无法直接控制模块的实时状态，而是需要输入一段由手册持有者提供的**指令序列（宏）**。一旦点击"运行"，系统将自动执行序列。两人必须对序列的最终结果有百分之百的把握。

### 视觉设计 (拆弹者屏幕)

```
┌────────────────────────────────┐
│  [运行队列] ──> [结果检测区]     │
│                                │
│  状态：等待输入                  │
│                                │
│  当前指令序列：                  │
│  [左转][抓取][右转][放下][焊接]  │
│                                │
│  可选操作块：                    │
│  [左转][右转][前推][抓取][放下]  │
│  [焊接][切割][加热][冷却]        │
│                                │
│  [  执行宏指令 (Execute)  ]      │
└────────────────────────────────┘
```

### 游戏流程与机制

1. **初始状态报告**：
   拆弹者首先看到模块上的几个初始零件（例如：一个带有蓝色外壳的芯片，旁边有一根红线），并通过离线消息或非实时文字报告给手册持有者。

2. **手册查表与逻辑推演**：
   手册持有者拥有一份极其复杂的《流水线操作手册》，根据初始状态（如蓝壳芯片+红线）推演出需要加工的最终产品要求：
   *示例要求*：“如果序列号为奇数，先剥离外壳，加热到50度，然后焊接红线，最后向左旋转输出。”

3. **编写宏指令**：
   手册持有者将复杂要求转化为拆弹者可输入的有限指令集。
   *指令集*：`[切割] -> [加热] -> [抓取] -> [焊接] -> [左转] -> [放下]`

4. **单次执行确认**：
   拆弹者将指令拖入执行序列并点击【执行】。
   一旦点击，动画开始播放，中途**无法暂停或撤销**。
   - 如果最终产物正确，模块解除。
   - 如果途中出现逻辑错误（如没有抓取就放下），模块直接爆炸或记录一次严重失误，并可能破坏零件导致重置。

### 机制亮点
- **减少实时压力，增加推演压力**：玩家不需要比拼说话速度，而是考验逻辑的严密性。
- **排错成本高**：因为无法实时干预，所有的推演必须在执行前反复确认。

## 模块二：📡 轨道卫星校准 (Orbital Satellite Calibration)

### 核心体验
引入**通信延迟**概念。拆弹者看到的雷达图是过去的数据，而手册持有者给出指令时，目标已经移动到了新的位置。必须提前计算提前量。

### 视觉设计 (拆弹者屏幕)

```
┌────────────────────────────────┐
│  📡 轨道通讯连接中...          │
│  延迟： 15秒 (Delay: 15s)      │
│                                │
│       [ 雷 达 扫 描 图 ]       │
│                                │
│          .   *                 │
│         .      .               │
│        .  [●]   * (目标)       │
│          .                     │
│                                │
│  发射角设定： [ 045 ] 度       │
│  拦截倒计时： [  启动  ]       │
└────────────────────────────────┘
```

### 游戏流程与机制

1. **时空错位**：
   拆弹者看到的星体目标位置（`*`）是**15秒前**的位置。目标按照特定的轨道规律移动。

2. **信息交换（高延迟）**：
   拆弹者告诉手册持有者目标当前显示的坐标或角度，并告知当前的"系统延迟时间"（如15秒）和目标的运动轨迹类型（例如：顺时针椭圆，速度慢）。

3. **预测计算**：
   手册持有者查阅《星历表》或《轨道动力学手册》。
   - 手册包含各种轨迹在特定时间流逝后的坐标计算公式。
   - 手册持有者必须计算出：**如果在收到消息后，再过15秒发射（或者立即发射但指令延迟生效），目标会出现在哪个角度？**
   - 例如：当前45度，每秒移动3度。沟通花了10秒，延迟15秒。发射将在25秒后到达目标点。预测角度 = 45 + (25 * 3) = 120度。

4. **盲狙发射**：
   拆弹者输入计算好的未来角度，并按下【启动】。
   模块进入"等待回应"状态，15秒后显示命中结果。若未命中，系统生成新的轨道，重试惩罚加剧。

### 机制亮点
- **真实的异步感**：将网络游戏常见的"延迟"概念实体化为游戏机制。
- **动态心算**：需要根据沟通的耗时动态调整参数。可以加入"指令确认收到"的时间戳系统，让手册持有者能准确知道从报告到执行经过了多少秒。

## 真·异步模式的其他潜在探索点

1. **信箱系统 (Dead Drop)**：
   双方不在同一时间游玩。玩家A（拆弹者）录下自己的操作界面状态并存入"信箱"，玩家B（手册持有者）半小时后打开信箱，写下解决方案。玩家A第二天登录查看并执行。

2. **多线程工作 (Multi-Threading)**：
   手册持有者同时处理多个异步模块的求助信息，像是一个忙碌的接线员，在各个模块的回复之间穿插切换。
