# ⏳ 时间膨胀模块 (Time Dilation)

> 核心机制：真正的异步协作，利用时间流速的不对称性进行解谜。
> 体验目标：让玩家感受跨越维度的信息传递。

---

## 核心设计思路

本模块致力于解决传统合作解谜游戏中“真·异步”的挑战。双方不仅信息不对等，连感知的**时间流速**也不同。

### 信息分割与时间差
- **拆弹者**：位于“快时空”，他们看到的事件发生得非常快，模块的提示转瞬即逝。
- **手册持有者**：位于“慢时空”，他们看到的计时器走得很慢，拥有充足的时间思考，但收到的信息存在延迟。

---

## 界面与交互设计

### 拆弹者视角 (快时空)
```
┌─────────────────┐
│                 │
│  [闪烁的符号阵列] │  ← 符号快速闪现（每秒变化一次）
│  △ O X □ ☆      │
│                 │
│  倒计时: 00:15  │  ← 快速跳动的专属倒计时
│                 │
│  [记录] [发送]   │  ← 只能截取当前瞬间发送给手册持有者
│                 │
└─────────────────┘
```
- 符号变化极快，人眼难以准确记忆。
- 必须抓准时机按下【记录】键，截取一帧画面。
- 按下【发送】后，等待手册持有者的回传指令。

### 手册持有者视角 (慢时空)
```
┌────────────────────────────────────────┐
│ 接收到的信号：                          │
│ [图片: △ O X □ ☆] (来自10秒前)        │
│                                        │
│ 解码规则表：                            │
│ 1. 若出现△和☆，正确点击顺序为：O → X → □ │
│ 2. 若出现X和□，正确点击顺序为：☆ → △ → O │
│ 3. 其他情况：从左到右依次点击            │
│                                        │
│ 传回指令选项：                          │
│ [指令A] [指令B] [指令C]                 │
│                                        │
│ 警告：信号传回需要5秒！                  │
└────────────────────────────────────────┘
```
- 接收到的是拆弹者过去的记录。
- 需要根据复杂的规则表进行解码。
- 发出指令后，指令会有固定延迟（例如5秒）才能到达拆弹者。

---

## 沟通与协作流程

1. **捕捉与发送**：拆弹者观察快速闪烁的符号阵列，在感觉合适的瞬间按下【记录】，然后【发送】给手册持有者。
2. **解码与预测**：手册持有者收到延迟的图像，开始查表解码。由于传回指令也有延迟，手册持有者必须计算好提前量。
3. **执行指令**：拆弹者在收到指令的瞬间，根据指令提示快速完成阵列中的按键操作。如果错过时机，指令作废。

### 极端情况：“时空悖论”
如果拆弹者在等待指令期间擅自操作并出错，时间流速会进一步加快，惩罚机制启动。

---

## 为什么这种设计适合“真·异步”？

1. **机制化延迟**：网络延迟和沟通延迟不再是游戏体验的阻碍，反而被包装成了核心游戏机制（时间膨胀/信号延迟）。
2. **节奏掌控**：拆弹者的紧张感（快）与手册持有者的运筹帷幄（慢）形成鲜明对比。
3. **预判的乐趣**：手册持有者需要预判拆弹者收到指令时的状态，增加了策略深度。
