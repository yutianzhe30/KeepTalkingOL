# ⏳ 真·异步合作机制与模块设计 (True Async Mechanics)

> 游戏模式：真·异步合作 (回合制/消息传递)
> 核心机制：**时停协议 + 预测执行 + 延迟反馈**
> 设计目标：探索 "Keep Talking and Nobody Explodes" 风格在非同时在线/文字交流场景下的可能性。

---

## 核心设计理念：真·异步 (True Asynchronous)

在传统的异步合作（如KTANE）中，玩家虽然信息不对称，但时间是同步流逝的（实时语音沟通）。
在"真·异步"模式中，玩家通过**类邮件/留言板**系统交互，时间线被切分。

### 交互循环框架：
1. **[拆弹者回合]**：炸弹时间暂停。拆弹者观察模块状态，撰写"状态报告"，点击发送后回合结束。
2. **[现实时间流逝]**：双方可以离线，等待对方回复。
3. **[手册方回合]**：手册持有者阅读报告，查阅规则，计算出解决步骤，撰写"指令包"，点击发送。
4. **[拆弹者回合]**：收到指令包。**时间恢复流动（倒计时开始）**，拆弹者必须在极短的实时窗口内精确执行预测的指令。

## 模块设计提案

### 1. 🔮 预测接线模块 (Predictive Wiring)

#### 拆弹者阶段（时停观察）
```
┌────────────────────────────────────┐
│ 状态：时停分析中                      │
├────────────────────────────────────┤
│ 模块视口：                           │
│  [1] 红色线，连接到 接口A             │
│  [2] 蓝色线，连接到 接口C             │
│  [3] 绿色线，连接到 接口B             │
│                                    │
│ 动态特征：                           │
│  指示灯目前是 黄色闪烁                │
├────────────────────────────────────┤
│ 留言板（发送给手册方）：              │
│ "三根线，1红连A，2蓝连C，3绿连B。      │
│ 指示灯黄闪。序列号末尾是奇数。"        │
│                                    │
│ [ 发送状态并结束回合 ]                │
└────────────────────────────────────┘
```
- 拆弹者无法进行任何剪线操作，只能观察和记录。

#### 手册方阶段（离线推导）
- 手册方收到留言，根据手册规则推导：
  - *规则1：黄闪+奇数序列号 → 剪断连向A的线，然后等待灯变绿。*
  - *规则2：绿灯后 → 剪断剩下的蓝色线。*
- 手册方打包指令发送回拆弹者。

#### 拆弹者执行阶段（实时挑战）
```
┌────────────────────────────────────┐
│ 状态：收到指令包。准备执行！          │
├────────────────────────────────────┤
│ 手册方留言：                         │
│ "先剪红线，等灯变绿，再剪蓝线。"      │
├────────────────────────────────────┤
│ [ 启动执行模块 (将恢复时间流动) ]      │
└────────────────────────────────────┘
```
- 点击启动后，**炸弹主倒计时恢复**，模块局部倒计时（如10秒）开始。
- 拆弹者必须严格按照预定计划行动。如果手册方的指令有误，或者拆弹者手抖剪错，直接引发Strike，并强制进入下一个"时停回合"重新评估。

### 2. 📡 盲盒路由模块 (Blind Box Routing)

#### 核心机制：盲目编程 (Blind Programming)
手册持有者需要编写一段类似宏命令的脚本，发给拆弹者"一键运行"。

#### 拆弹者界面（回合1）
- 看到一个 4x4 的网格图，起点和终点，以及一些随机分布的障碍物（炸弹）。
- 拆弹者把网格的布局（障碍物坐标）发给手册方。
- *"起点在(0,0)，终点在(3,3)，(1,1)和(2,2)有雷。"*

#### 手册方界面（回合2）
- 手册方根据拆弹者给的坐标，绘制出安全路线。
- 但是，手册方**不能**直接说路线，必须组合系统提供的**指令块**（如：`前进2步`、`右转`、`如果遇到墙则左转`）。
- 打包这段指令序列（如 `[F2, R, F1, L, F1]`）发送。

#### 拆弹者界面（回合3）
- 收到一条**加密的指令序列**，拆弹者无法查看里面的具体内容，只能看到一个 `[ 运行路由程序 ]` 按钮。
- 点击运行，看着光标在网格上自动行走。
- 走错直接爆炸。走对解除。
- **乐趣点**：手册方承担所有规划责任，拆弹者体验"拆盲盒"的刺激感。

### 3. 🧪 延迟化学混合 (Delayed Alchemy)

#### 核心机制：时间错位的状态变化
化学物质在混合后，需要经过一段**现实时间**（如系统判定的回合轮转）才会发生变化，双方必须预测未来的状态。

#### 流程演示
1. **拆弹者**：发现一个烧杯，里面是"紫色液体"，温度"30度"。发送给手册方。
2. **手册方**：查表得知，紫色液体+30度，需要在里面加入"催化剂A"。发送指令。
3. **拆弹者**：加入催化剂A。系统提示："反应中...请等待下一个回合"。拆弹者转去处理其他模块。
4. （一回合后）**拆弹者**：烧杯液体变成了"橙色冒泡"，发送给手册方。
5. **手册方**：查表，橙色冒泡意味着反应成功，现在需要立刻"冷却"。
6. **拆弹者**：执行冷却，模块解除。

- **挑战**：如果在等待反应的期间，炸弹的整体温度升高（由于其他模块的失误），可能会导致化学模块产生不同的变异状态，需要重新沟通。

## 真·异步模式带来的设计优势

1. **降低社交门槛**：不需要双方同时在线，不需要语音，适合碎片化时间的社恐玩家。
2. **强化"责任感"与"甩锅"乐趣**：指令白纸黑字写在留言板上，出错时可以明确查出是"你给错指令"还是"我操作失误"。
3. **独特的节奏感**：将KTANE的"持续高压"转变为"长期的悬念期待"与"瞬间的执行爆发"交替。
