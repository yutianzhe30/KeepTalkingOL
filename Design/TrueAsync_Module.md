# ⏳ 真·异步合作设计提案 (True Asynchronous Game Modes)

> 探索“时停”与“回合制消息传递”的核心机制
> 摆脱同时在线的限制，实现“留言板式”的合作拆弹

---

## 核心设计理念：基于时间冻结的拆弹

传统的《Keep Talking and Nobody Explodes》要求两名玩家必须同时在线并进行实时语音交流。
本项目 (KeepTalkingOL) 的核心亮点是 **真·异步 (True Asynchronous)**。

*   **拆弹者 (Defuser)**：面临炸弹，但在特定交互下可以**冻结时间**（Time Freeze），提取当前炸弹状态，并生成“求助信息”。
*   **专家 (Expert/Manual Holder)**：不在线。通过论坛、聊天软件或游戏内“漂流瓶”接收到“求助信息”。专家进行离线解谜（Offline Solving），然后生成一段**“预测性指令”** (Predictive Instructions)。
*   **执行 (Execution)**：拆弹者收到指令后，输入到炸弹中，或者炸弹自动按指令进行**批量执行** (Batch Execution)。

---

## 提案模块 1：🔮 预测调度器 (Predictive Scheduler)

### 核心机制
这个模块无法通过实时沟通解决，因为炸弹状态变化极快，且需要极高的操作精度。唯一的方法是暂停时间，计算出未来的操作序列，然后让机器代为执行。

### 拆弹者屏幕视图

```text
┌──────────────────────────────┐
│  [ 冻结/分析按钮 (时停) ]    │
│                              │
│  当前转盘状态 (每秒旋转):    │
│  [ A ] [ B ] [ C ] [ D ]     │
│                              │
│  指令队列 (最多输入5条):     │
│  1. [________]               │
│  2. [________]               │
│  3. [________]               │
│  [ 执行队列 (恢复时间) ]     │
└──────────────────────────────┘
```

### 游戏流程

1.  **时停与提取 (Time Freeze & Extraction)**：
    拆弹者按下“冻结/分析按钮”，游戏内的时间暂停。
    系统生成一串“状态快照码” (State Snapshot Code)，例如：`S: A-B-C-D | T: 45s | SN: 18XYZ`。
    拆弹者将这串代码发送给专家（可以通过微信、Discord 或游戏内的留言系统）。
2.  **离线解谜 (Offline Solving)**：
    专家收到快照码，开始查阅手册。
    手册上写明了转盘的旋转规律、序列号的影响，以及如何达成目标状态。
    专家在纸上或脑中进行推演：“如果现在是 A-B-C-D，那么 3 秒后会变成 D-A-B-C，这时候按下 1 号按钮，然后等待 2 秒……”
3.  **预测性指令 (Predictive Instructions)**：
    专家得出一套操作指令序列，例如：`WAIT 3, PRESS 1, WAIT 2, PRESS 4`。
    专家将指令序列发送回拆弹者。
4.  **批量执行 (Batch Execution)**：
    拆弹者收到指令，将其输入到炸弹的“指令队列”中。
    拆弹者点击“执行队列”，时间恢复流动，炸弹开始自动按照预定指令执行操作。
    如果专家的预测正确，模块解除；如果预测错误，指令执行失败，模块重置并扣除时间。

## 提案变体 2：📜 时空漂流瓶 (Time-Shift Bottle)

### 核心机制
这是一个社区驱动的变体模式。炸弹的倒计时非常长（例如 24 小时），玩家可以在炸弹即将爆炸前的任何时候介入。

### 拆弹者体验

1.  **上线接手**：玩家打开游戏，发现一个正在倒计时的炸弹，旁边有一个“留言板”或一堆“漂流瓶”。
2.  **查看前人留言**：
    留言 1 (3小时前)：“我试了红线，炸了。别剪红线！——玩家 A”
    留言 2 (1小时前)：“迷宫模块我测出了起点在左上角，但是卡在了第三步。谁来接力？——玩家 B”
    留言 3 (10分钟前)：“根据说明书，序列号有元音，频率模块应该是输入 58。我没时间了，下一个上线的兄弟帮忙输入一下！——玩家 C”
3.  **接力执行**：当前玩家根据前人的留言，避免踩坑，执行正确的操作。
4.  **留下遗言/进展**：如果当前玩家也未能完全拆除，他们可以写下自己发现的新线索，生成新的漂流瓶，留给下一个上线的玩家。

### 这个模式的意义
将双人合作扩展为“跨越时空的社区合作”。利用互联网的异步特性，让互不相识的玩家为了同一个目标（拆掉这个 24 小时倒计时的炸弹）进行接力。

---

## 为什么这种“真·异步”是可行的？

1.  **降低门槛**：不再需要找一个“现在刚好有空并且愿意和你语音”的朋友。你可以在摸鱼时发个快照，朋友下班后帮你解开。
2.  **增加策略深度**：从“反应能力与实时沟通”转变为“严谨的逻辑推演与指令编程”。
3.  **符合设定**：完美的体现了“黑客骇入系统提取数据，场外专家分析数据发送破解脚本”的赛博朋克感。
